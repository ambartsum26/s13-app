# Ассистент по участкам

Небольшое браузерное приложение для ведения городов, участков, истории выдач и базы возвещателей с хранением данных в Firebase Firestore.

## Структура

- `index.html` — базовая HTML-разметка и минимальные fallback-стили.
- `app.js` — точка входа и подключение модулей.
- `app-core.js` — Firebase, города, участки, возвещатели, выдача/сдача и история.
- `app-auth.js` — вход владельца через Firebase Authentication.
- `app-ui.js` — общий внешний вид и компоновка приложения.
- `app-cards.js` — оформление и поведение карточек участков.
- `app-popups.js` — модальные окна, Esc, закрытие по фону и блокировка прокрутки.
- `s13-export.js` — экспорт регистра S-13.
- `firestore.rules` — серверное ограничение доступа к Firestore по UID владельца.
- `tests/auth.test.cjs` — проверки логики авторизации без обращения к рабочей базе.

## Принцип изменений

Данные Firestore изменяются только через действия пользователя в `app-core.js`. UI-модули не удаляют и не перезаписывают данные базы.

Перед крупными рефакторингами сохраняются резервные ветки GitHub, чтобы рабочее состояние можно было восстановить.

## Вход владельца

`app-auth.js` использует Firebase Authentication. Приложение не читает Firestore, пока Firebase не подтвердит UID владельца.

На новом устройстве при первом успешном входе нужно один раз указать e-mail владельца и пароль. После успешной проверки e-mail сохраняется только локально в браузере, а при следующих входах отображается только поле **«Пароль»**. Сам пароль нигде в GitHub, `localStorage` или Firestore не сохраняется. Кнопка **«Сменить аккаунт»** очищает запомненный e-mail и возвращает полный вход по почте и паролю.

Сеанс Firebase ограничен текущей вкладкой. После выхода подписки Firestore отключаются, открытые формы закрываются, а загруженные данные удаляются из интерфейса.

`firestore.rules` ограничивает чтение и запись тем же UID владельца. Ограничение в JavaScript не заменяет серверные правила. GitHub Pages не публикует правила Firebase автоматически: их нужно опубликовать отдельно в консоли Firestore после проверки входа владельца. Не публикуйте правила до проверки UID и рабочего входа.

Проверки без обращения к рабочей базе: `node tests/auth.test.cjs`. Они покрывают отказ без входа и чужому UID, вход владельца, выход, ошибки входа, отключение подписок и запоздавшие ответы. Реальные правила проверяются отдельно в симуляторе Firebase.

Резервные копии данных и пароли нельзя сохранять в публичном репозитории.
