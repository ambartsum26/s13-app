# Ассистент по участкам

Браузерное приложение для ведения городов, участков, истории выдач и базы возвещателей с хранением рабочих данных в Firebase Firestore.

## Архитектура

Исходный код разделён на небольшие модули. `app.js` — точка входа; `app-auth.js` отвечает за Firebase Authentication; `app-data.js` — за транзакционные изменения и защиту от конфликтов; `app-core.js` — за прикладную логику; отдельные модули обслуживают карточки, поиск, сортировку, всплывающие окна, hardening, Apple/Samsung UI и экспорт S-13.

Production-страница не исполняет Tailwind Play CDN и не загружает Firebase JavaScript с `gstatic`. В репозитории хранятся воспроизводимо собранные `tailwind.generated.css` и `app.bundle.js`. Font Awesome 6.4.0 также хранится локально в `vendor/fontawesome`; лицензия и SHA-256 контрольные суммы лежат рядом с файлами.

Исходные модули сохраняются в репозитории как читаемый код. `scripts/build-production.mjs` собирает production bundle из тех же модулей, заменяя Firebase CDN-imports на закреплённый npm-пакет `firebase@10.8.0`.

## Данные и целостность

Firestore изменяется только явными действиями пользователя. История выдач сохраняется транзакционно, проверяется на некорректные даты и пересекающиеся периоды. Для операций, где важна уникальность, используются служебные документы `appLocks`, поэтому параллельные добавления/переименования повторно проверяются внутри транзакции.

Редактирование существующих данных использует оптимистическую проверку: если то же поле успела изменить другая вкладка, сохранение отклоняется как конфликт вместо молчаливой перезаписи. Неизменённые поля другой вкладки сохраняются.

Старые документы без необязательных `mapUrl`/`russianSpeakers` нормализуются к значениям, которые видит интерфейс. Повреждённая история не должна ронять отрисовку; изменение такой записи блокируется до исправления.

## Авторизация и Firestore Rules

Интерфейс входа работает в режиме «только пароль». Firebase Authentication проверяет пароль, а приложение дополнительно разрешает работу только ожидаемому UID владельца. До подтверждения сессии подписки Firestore не запускаются; после выхода подписки останавливаются и данные очищаются из интерфейса.

`firestore.rules` — основной серверный барьер: известные коллекции доступны только владельцу, неизвестные пути закрыты правилом default-deny. Правила компилируются в Firestore Emulator в каждом quality-gate.

Важно: GitHub Pages не публикует `firestore.rules` в рабочий Firebase-проект. После изменения правил их нужно отдельно развернуть в Firebase, например:

```bash
firebase deploy --only firestore:rules
```

Нельзя временно заменять рабочие правила на `allow read, write: if true`.

## Production-сборка

Используемые версии сборки закреплены в CI:

- Node.js 24;
- Tailwind CSS 3.4.17;
- esbuild 0.28.2;
- Firebase Web SDK 10.8.0;
- Firebase CLI 15.29.0;
- Java 21 для Firestore Emulator.

Ручная пересборка CSS:

```bash
npx --yes tailwindcss@3.4.17 -c tailwind.config.cjs -i tailwind.input.css -o tailwind.generated.css --minify
```

Ручная пересборка JS после установки `esbuild@0.28.2` и `firebase@10.8.0`:

```bash
node scripts/build-production.mjs
```

Сгенерированные файлы являются частью проверяемого production-артефакта. CI пересобирает их заново и требует побайтового совпадения с закоммиченными версиями.

## Автоматические проверки

`Application regression checks` выполняет:

1. проверку синтаксиса JavaScript и всех тестов;
2. воспроизводимую пересборку Tailwind и `app.bundle.js`;
3. проверку SHA-256 локальных Font Awesome assets;
4. проверку отсутствия Tailwind/CDNJS/Firebase runtime CDN в production HTML/bundle;
5. компиляцию `firestore.rules` через Firestore Emulator;
6. запуск всех файлов `tests/*.test.cjs`.

Сейчас покрываются авторизация, целостность данных и конфликты, S-13, сортировка и двухколоночная раскладка возвещателей, поиск/picker, каскадная анимация и security/hardening-регрессии. `CodeQL` отдельно анализирует JavaScript/TypeScript на push/PR и по недельному расписанию. Dependabot еженедельно проверяет GitHub Actions dependencies.

Локальный запуск всех регрессионных тестов:

```bash
for test in tests/*.test.cjs; do node "$test" || exit 1; done
```

## Поиск и список возвещателей

Поиск нормализует регистр, диакритику и кириллицу и умеет искать слова независимо от порядка. Сортировка идёт по фамилии при отображении «Имя ФАМИЛИЯ». При одинаковой фамилии сохранённый `gender` позволяет ставить мужчину выше женщины. На широком экране две колонки читаются сверху вниз и одинаковая фамилия не разрывается между колонками.

Тестовые фикстуры в публичном репозитории должны быть только синтетическими. Реальный список возвещателей, экспорт Firestore, резервные копии и другие персональные данные нельзя добавлять в GitHub.

## Экспорт S-13

При экспорте выбирается служебный год; выдачи, пересекающие этот период, попадают в соответствующий S-13. Незавершённые выдачи предыдущих лет сохраняют фактические даты. После заполнения первой страницы создаются дополнительные листы. Экспорт не изменяет историю в Firestore и не пропускает молча некорректные даты.

## Release discipline

Рекомендуемый путь изменения: отдельная ветка → pull request → зелёный `quality-gate` и CodeQL → merge. Прямые изменения `main` использовать не следует.

Для максимальной защиты репозитория в GitHub Settings нужно включить ruleset/branch protection для `main`: запретить прямые изменения, требовать pull request и успешный `quality-gate` перед merge. Это настройка самого GitHub-репозитория, а не файл приложения.

GitHub Pages также должен публиковать только проверенную ревизию. Если Pages настроен на автоматическую публикацию каждого push в `main`, зелёный CI остаётся проверкой качества, но не техническим блокиратором deployment — это нужно учитывать в настройках Pages/Actions.

## Секреты и публичные данные

Пароли и приватные выгрузки никогда не должны храниться в репозитории. Firebase Web API key и клиентская Firebase-конфигурация по модели Firebase находятся в браузерном коде и сами по себе не заменяют авторизацию; безопасность данных должна обеспечиваться Authentication, Firestore Rules и ограничениями ключа в Google Cloud/Firebase.

Перед крупной миграцией данных делайте резервную копию вне публичного GitHub и не меняйте имена коллекций `cities`, `territories`, `publishers`, `appLocks` без отдельного плана миграции.
